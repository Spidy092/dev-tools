WHY USE DEVTOOLKIT?

Small online utilities are easy. Real project folders are where the friction starts.

01

Bulk by default

Work with one file, a mixed selection, or complete directory trees instead of repeating the same task file by file.

02

Understand first

Folder Intelligence surfaces file types, large files, totals, and useful groups before an operation begins.

03

Preview + presets

Reuse settings and review planned changes before expensive or mutating operations.

04

Self-host when files matter

Run DevToolkit on infrastructure you control instead of uploading sensitive project files to unrelated utility sites.

BUILT IN PUBLIC

Open source, understandable, and designed to grow.

DevToolkit is MIT licensed and intentionally uses Express, EJS, and modular vanilla JavaScript. The project includes contribution guidelines, structured issue templates, security guidance, tests, CI, a roadmap, and release conventions.

For sensitive workloads, self-hosting keeps the processing server under your control. DevToolkit describes which work happens in the browser and which work is server-processed.

Read the contribution guide →
$ git clone https://github.com/Spidy092/dev-tools.git
$ cd dev-tools
$ npm ci
$ cp .env.example .env
$ npm test
$ npm start
DevToolkit running at http://localhost:3000
